# すべての出力は日本語で行ってください

ユーザーへの説明、質問、進捗報告をすべて日本語で出力してください。

# /ship コマンド

作業完了後にリポジトリをクリーンな状態にして、commit → push → PR作成を行います。

## 引数

<input_argument> $ARGUMENTS </input_argument>

引数が指定された場合はPRタイトルまたはブランチ名として使用します。

---

## Phase 0: ブランチ確認（重要）

**mainブランチへの直接コミットは禁止**

```bash
# 現在のブランチを確認
git branch --show-current
```

### mainまたはmasterにいる場合

1. ユーザーに新しいブランチ名を確認
2. ブランチを作成して切り替え

```bash
git checkout -b [branch-name]
```

**ブランチ名の提案例**:
- 機能追加: `feature/機能名`
- バグ修正: `fix/問題の簡潔な説明`
- ドキュメント: `docs/内容`
- リファクタリング: `refactor/対象`

---

## Phase 1: クリーンアップ

### 1.1 現在の状態を確認

```bash
git status
```

### 1.2 不要ファイルを特定

以下のようなファイルがないか確認し、ユーザーに削除を提案：

**よくある不要ファイル**:
- 一時的に作成したテストファイル（`test_*.rb`, `debug_*.rb`等）
- デバッグ用のファイル
- ログファイル（`*.log`）
- キャッシュファイル（`*.cache`, `tmp/`内のファイル）
- システムファイル（`.DS_Store`, `Thumbs.db`）
- バックアップファイル（`*.bak`, `*.orig`, `*~`）
- エディタの一時ファイル（`.swp`, `.swo`）

### 1.3 必要なファイルを確認

以下のディレクトリに必要なファイルがあるか確認：
- `docs/` - ドキュメント
- `plans/` - プランファイル

### 1.4 不要ファイルを削除

ユーザーの確認後、不要ファイルを削除：

```bash
# 追跡されていない不要ファイルを削除
rm [不要ファイル]

# 変更を破棄（必要な場合）
git checkout -- [ファイル]
```

**目標**: コミット後にリポジトリがきれいな状態になること

---

## Phase 2: ステージング

### 2.1 ファイルをステージング

```bash
git add .
```

### 2.2 ステージング内容を確認

```bash
git status
git diff --staged
```

### 2.3 ユーザーに確認

変更内容をユーザーに提示し、問題ないか確認する。

---

## Phase 3: コミット

### 3.1 変更内容を分析

ステージングされた変更を分析し、適切なコミットメッセージを生成。

### 3.2 コミットメッセージのフォーマット

Conventional Commit形式を使用：

```
<type>(<scope>): <description>

[optional body]
```

**type一覧**:
- `feat`: 新機能
- `fix`: バグ修正
- `docs`: ドキュメント
- `style`: フォーマット変更
- `refactor`: リファクタリング
- `test`: テスト追加・修正
- `chore`: その他の変更

### 3.3 コミット実行

```bash
git commit -m "$(cat <<'EOF'
<type>(<scope>): <description>

<body>
EOF
)"
```

---

## Phase 4: プッシュ

```bash
git push -u origin $(git branch --show-current)
```

---

## Phase 5: PR作成

### 5.1 PR作成

```bash
gh pr create --title "[タイトル]" --body "$(cat <<'EOF'
## Summary
- 変更内容の要約

## Changes
- 変更ファイル一覧

## TODO: デプロイ後の作業

### 他のWorktree環境
- [ ] mainにマージ後、他のworktreeでgit pullを実行

### Staging環境
- [ ] デプロイ確認
- [ ] 動作確認: [確認項目を記載]

### Production環境
- [ ] デプロイ確認
- [ ] マイグレーション実行（必要な場合）
- [ ] 環境変数設定（必要な場合）
- [ ] 動作確認: [確認項目を記載]
EOF
)"
```

### 5.2 完了報告

- PRのURLをユーザーに報告
- 次のステップ（レビュー依頼、マージ等）を提案

---

## 注意事項

1. **mainへの直接コミット禁止**: 必ずブランチを切ってからコミット
2. **クリーンな状態**: 不要ファイルは必ず削除してからコミット
3. **ユーザー確認**: 各フェーズでユーザーに確認を取る
4. **TODOを忘れない**: PRにはデプロイ後の作業を必ず記載
